# 孕育小家 · 首页照护升级 — 完整手工测试步骤

> 用途：按顺序点一点就能验收本次「首页每日照护仪表盘」升级。  
> 原则：每一步都写清 **在哪里操作 → 点什么 → 期望看到什么**。  
> 底部导航必须始终只有：**首页 / 对话 / 我的**（没有 Journey / Track / Agent Tab）。

- macOS + Flutter（建议与仓库锁版本一致，见根目录 `README.md`）

- 工程目录是 **`AI-Mom-Baby/app`**（有 `pubspec.yaml`），不是仓库根目录

或在 Android Studio：

1. **File → Open** 打开 `AI-Mom-Baby/app`

3. Run 配置带：`--flavor dev --dart-define-from-file=env/dev.json`

## 2. 首页模块清单（先认界面）

在 **首页** 从上到下应大致看到（部分模块可能因档案为空而隐藏，见后文）：

| 顺序 | 模块标题 / 特征 | 作用 |
|------|-----------------|------|
| 1 | 顶部一句提示 + 按钮（如「已服用」） | 小暖情境提示（不是大聊天气泡） |
| 2 | 旅程大卡片（chip + 孕周/周期文案 + 插图） | 当前旅程状态；可点进详情 |
| 3 | **和谁聊聊** + 横向角色（小暖/林医生/苏心/阿嬷） | 进对话 |
| 4 | **今日饮水** + 进度 + **+250 / +500 / 自定义** | 喝水打卡 |
| 5 | **今日状态**（饮水/睡眠/体重/不适记录）+ **心情** chips | 健康快照 |
| 6 | **今日用药提醒**（备孕/孕期常出现） | 孕维打卡 |
| 7 | **今日照护** + 任务勾选 | 今日任务 |
| 8 | **今日饮食关注** + 免责声明 | 轻量营养提示 |

**期望：**

- [ ] 角色区是横向紧凑入口，**不是**占满首屏的大 2×2 主视觉
- [ ] 模块之间有空隙，一眼能分清区块

## 3. 场景 A：配置「备孕」并验收旅程

### 步骤 3.1 — 进入孕期档案

1. 点底部 **我的**
2. 点列表里的 **孕期**（进入「孕期与生育」）

### 步骤 3.2 — 设为备孕中

1. 在「妊娠状态」中点选 **备孕中**
2. 点页面保存（右上角或底部保存按钮，以实际 UI 为准）
3. 再点 **编辑末次月经 / 预产期 / 分娩日**
4. 填写 **末次月经**（例如选「今天往前推 12 天」的日期）
5. **清空预产期、清空分娩日**（若有清除按钮就点清除）
6. 保存并返回，直到回到 **我的**，再点 **首页**

**期望（首页旅程卡片）：**

- [ ] 阶段 chip 类似 **备孕**（或备孕相关文案）
- [ ] 主文案出现 **周期第 N 天**（有末次月经时），或至少 **备孕中**
- [ ] **不会**同时出现「孕 N 周 + 预产期」这类孕期主信息（无关信息不堆叠）

### 步骤 3.3 — 打开旅程详情

1. 在首页点旅程大卡片（整块可点）

**期望：**

- [ ] 进入标题为 **我的旅程** 的页面
- [ ] 有说明：信息来自本地档案、未填字段不编造
- [ ] 有就医免责声明
- [ ] 左上角返回可回到首页

### 步骤 3.4 — 备孕任务

1. 回到首页，找到 **今日照护**

**期望至少能看到备孕相关任务之一（名称可能略同）：**

- [ ] 喝水打卡
- [ ] 叶酸/备孕维
- [ ] 心情打卡
- [ ] 轻松散步

## 6. 小暖提示（顶部 nudge）

> 提示优先级大致为：未服孕维 → 饮水不足 → 未记心情 → 档案未完善。  
> 测试时建议先用 **场景 B（怀孕中）**，并尽量清空「今日」打卡，便于看到提示。

### 步骤 6.1 — 看到孕维提示

1. 确保妊娠状态为 **怀孕中** 或 **备孕中**
2. 若今日已勾选孕维：在首页 **今日用药提醒** 把 **叶酸 / 孕维** 开关关掉；或到 **我的 → 生活方式** 取消「今日已服孕维/叶酸」并保存
3. 回首页顶部

**期望：**

- [ ] 出现类似文案：*今天的叶酸/孕维还没打卡…*
- [ ] 按钮文案为 **已服用**
- [ ] 是一小条提示卡，**不是**巨大聊天气泡 / 机器人头像墙

### 步骤 6.2 — 点「已服用」

1. 点 **已服用**

**期望：**

- [ ] 顶部提示消失或换成下一条（如饮水/心情）
- [ ] **今日用药提醒** 里「叶酸 / 孕维」为已开启状态（若该卡可见）

### 步骤 6.3 — 饮水提示

1. 若今日饮水已经很多：用 **自定义** 把饮水量改成很小（如 `0` 或 `100`），便于触发「喝得少」提示  
   （若自定义不允许 0，用尽可能小的正数，或清数据见附录）
2. 确保孕维已打卡，以便优先级落到饮水
3. 看顶部提示

**期望：**

- [ ] 文案类似：*今天饮水还不多…*
- [ ] 按钮为 **喝水 +250**

### 步骤 6.4 — 点「喝水 +250」

1. 点 **喝水 +250**

**期望：**

- [ ] **今日饮水** 进度数字增加约 250ml
- [ ] 顶部提示可能变为心情提示，或消失

### 步骤 6.5 — 心情提示

1. 若已有心情：在 **今日状态 → 心情** 再点一次当前选中项，清除选中
2. 确保孕维已服、饮水不太少（或已超过目标的 25%）
3. 看顶部

**期望：**

- [ ] 文案类似：*记一下今天的心情…*
- [ ] 按钮 **去记录**
- [ ] 点 **去记录** 后页面向下滚到 **心情** 区域

## 7. 饮水模块（完整操作）

前提：在 **首页**，找到 **今日饮水**。

### 步骤 7.1 — +250

1. 记下当前进度文案（例如 `0 ml / 2000 ml`）
2. 点 **+250**

**期望：**

- [ ] 进度标签增加约 250
- [ ] 进度条/环形指示有变化（不必完美动画，但数值要对）

### 步骤 7.2 — +500

1. 再点 **+500**

**期望：**

- [ ] 在上一步基础上再增加约 500

### 步骤 7.3 — 自定义

1. 点 **自定义**
2. 在弹出层输入 `1200`（单位 ml）
3. 确认/保存（以弹层按钮为准）

**期望：**

- [ ] 今日饮水量变为 **1200**（绝对值覆盖，不是在原值上再加）
- [ ] 弹层关闭，模块标签与进度同步

### 步骤 7.4 — 与「我的」核对

1. 点底部 **我的**
2. 看顶部附近的 **今日** 摘要 chips（有饮水相关显示则记下）
3. 再进 **生活方式**
4. 看字段 **今日已饮水 (ml)**

**期望：**

- [ ] 与首页显示的饮水量一致（允许四舍五入到整数）

### 步骤 7.5 — 反向同步

1. 在 **生活方式** 把「今日已饮水」改成 `800`，保存
2. 返回 **首页**

**期望：**

- [ ] **今日饮水** 显示约 `800`（与目标对比的进度同步）

**期望：**

- [ ] 芯片变为类似 **睡 7.5h**

### 步骤 8.2 — 体重

1. 点 **体重 —**（或已有体重芯片）
2. 输入 `62.4`，保存

**期望：**

- [ ] 芯片变为类似 **体重 62.4kg**

### 步骤 8.3 — 心情

1. 在 **心情** 区域依次点：`平静`、`开心`、`疲惫`、`焦虑`、`低落`（不必全测，至少测 2 个）
2. 点中一个后，再点同一个

**期望：**

- [ ] 点选后该 chip 呈选中态，且同时只有一个选中
- [ ] 再点同一 chip 可取消选中
- [ ] 下方有文案：*严重不适请及时就医，这里仅作生活记录。*

### 步骤 8.4 — 不适记录

1. 点 **不适记录**
2. 弹层标题类似 **快速记录不适**
3. 勾选例如：**恶心**、**疲劳**
4. 确认有就医提示文案
5. 点 **保存**（或同等按钮）

**期望：**

- [ ] 弹层关闭，无崩溃
- [ ] （可选）再次打开不适记录，能看到上次勾选被带出或可再次编辑

### 步骤 8.5 — 与「我的」同步

1. **我的** → 看 **今日** 摘要是否出现睡眠/体重/心情/孕维等
2. **生活方式** 中 **今日心情 / 今日体重** 是否与首页一致

**期望：**

- [ ] 与首页一致（同源 `todayCheckIn`）

## 附录 A. 首页模块「看不见」时怎么办

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| 没有顶部小暖提示 | 孕维已服 + 水够多 + 已有心情 | 关掉孕维开关、降低饮水量、取消心情后再看 |
| 没有「今日用药提醒」 | 产后且无用药列表、或孕维已服且无其它药 | 改回备孕/怀孕，或在用药档案加药 |
| 旅程不像预期 | 预产期/分娩日/妊娠状态互相冲突 | 按场景 A/B/C 清掉无关日期再保存 |
| 今日照护很少 | 阶段/孕周不匹配模板 | 用场景 B 填孕周 24 再看 |

## 附录 B. 已知可接受缺口（不必当 Fail）

- 备孕「周期第 N 天」是按末次月经的 **简单 28 天估算**，不是医学级排卵监测。
- 有本地事件日志，但 **没有** 体重/饮水历史折线图。
- 「我的」下尚未单独合并成完整 Settings 页。
- 产品核心仍是 AI 陪伴；首页是每日照护，**不是**医院系统仪表盘。

## 附录 C. 测试账号建议

若 App 支持本地多账号（「我的」里账号切换/新建）：

1. 建账号「备孕测试」→ 只跑场景 A + 第 6–11 节  
2. 建账号「孕 24 周」→ 只跑场景 B + 第 6–11 节  
3. 建账号「产后」→ 只跑场景 C  

可减少同一账号日期字段互相覆盖带来的混淆。
